# Контроль проектных рисков

Рабочий репозиторий прототипа для быстрого анализа состояния портфеля проектов руководителем.

## Статус

Intake завершён. Текущая задача — `I001`; актуальный workflow/status см. в `workflow/STATE.md`.

## Цель

Дать руководителю за несколько секунд понять состояние портфеля: автоматически и прозрачно классифицировать проектные риски, показать проблемные проекты и объяснить приоритетные действия.

## Архитектурный подход

Выбран минимальный профиль `STATIC_SINGLE_FILE`: самодостаточный `index.html` на HTML/CSS/JavaScript без обязательного backend, контейнера, package manager и внешних runtime-зависимостей.

Обязательная функциональность полностью детерминирована и не зависит от внешнего ИИ. Опциональная ИИ-рекомендация допускается только как дополнительный браузерный сценарий с операторским токеном текущей сессии (`OPERATOR_SESSION_BYOK`) и не должна ломать основной демонстрационный поток.

## Алгоритм интегрального риска

Для проекта рассчитывается прозрачный балл 0–100:

- просрочка: `min(30, Просрочка_дней × 3)`;
- открытые риски: `min(15, Открытые_риски × 3)`;
- критические риски: `min(50, Критические_риски × 25)`;
- выполнение: `+10` при выполнении `<50%`, `+5` при `50–69%`, иначе `0`.

Итог ограничивается 100. Уровни: `0–9 низкий`, `10–24 средний`, `25–49 высокий`, `50–100 критический`. В карточке проекта должны быть видны составляющие оценки, чтобы результат был воспроизводимым.

## Запуск

Реализация приложения ещё не создана; её создаёт `I001`.

После выполнения первого runnable slice канонический путь должен быть таким:

### Первый запуск из чистого checkout

1. Получить/клонировать репозиторий и перейти в его корень.
2. Открыть `index.html` в современном браузере. На Linux допустима команда:

```bash
xdg-open index.html
```

Установка зависимостей и сборка не требуются.

### Последующие запуски

Повторно открыть тот же `index.html`; дополнительная настройка для основной функциональности не требуется.

Если используется опциональный ИИ, оператор вводит в интерфейсе только текущие значения `endpoint`, `model` и `token`. Токен должен храниться только в памяти страницы, не отображаться обратно и вводиться заново после перезагрузки/закрытия.

## Демонстрационный сценарий

1. Открыть приложение и демонстрационный набор проектов.
2. Показать автоматическую оценку и панель портфеля.
3. Загрузить CSV и показать обновлённые результаты.
4. Отфильтровать проекты по уровню риска и этапу.
5. Открыть критический проект, показать причины оценки, исходный комментарий и рекомендуемое действие.
6. При доступном провайдере — показать дополнительную ИИ-рекомендацию; при недоступности — понятный неблокирующий статус.
